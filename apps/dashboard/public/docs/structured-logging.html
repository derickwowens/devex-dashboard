Structured Logging Standard

Federated DevEx Platform Error Framework

v1.0.0 Last Updated: January 2026 Owner: Platform Engineering

🎯 The Philosophy: Fast Triaging

Every second spent researching "who owns this error?" is a second not spent fixing it. Our structured logging standard eliminates this waste entirely.

❌ Traditional Approach

"Error: Connection failed"
Who owns this? Where do I file a ticket? Let me search Confluence for 30 minutes...

✅ Our Approach

"AUTH-00142: Connection failed: Platform Auth: auth-team@company.com: #auth-incidents"
Instant triage. Zero research. File ticket immediately.

Core Principle

"Every error message must contain everything needed to route a ticket—no exceptions, no lookups required."

The Standard Error Format

All errors in the ecosystem MUST use this format:

[ErrorCode]: [ErrorString]: [TeamName]: [TeamEmail]: [IncidentGroup]
Component Description Example
ErrorCode Unique identifier (SDK_PREFIX-NUMERIC_ID) AUTH-00142
ErrorString Human-readable error message Token refresh failed
TeamName Responsible team Platform Auth
TeamEmail Team contact email auth-team@company.com
IncidentGroup Slack/Teams channel for incidents #auth-incidents

Real-World Examples

Authentication Error
AUTH-00142: Token refresh failed: invalid grant: Platform Auth: auth-team@company.com: #auth-incidents
Pipeline Failure
PIPE-00034: Pipeline execution failed: build step timeout: DevOps: devops@company.com: #devops-incidents
Telemetry Alert
TEL-00023: Memory threshold exceeded - 95% utilization: Observability: observability@company.com: #obs-incidents

Stack Trace Format

The error string MUST appear as the first line of any stack trace:

AUTH-00142: Token refresh failed: invalid grant: Platform Auth: auth-team@company.com: #auth-incidents
    at AuthService.refreshToken (/src/auth/service.ts:142)
    at async TokenManager.refresh (/src/auth/token.ts:67)
    at async middleware (/src/middleware/auth.ts:23)

Benefits

⚡ Faster Triage
Error ID immediately identifies the issue and owner
🎯 Accurate Routing
Tickets go to the right team automatically
🚫 Reduced Toil
No more "who owns this?" investigations
📊 Better Metrics
Filter and aggregate by SDK, team, or error type

Implementation Example

import { sdk } from '@federated/facade';

// Capture an error with full structured metadata
sdk.errors()
  .capture(error)
  .withErrorId('AUTH-00142')
  .withSdk('@federated/auth')
  .withOwnership({
    team: 'Platform Auth',
    email: 'auth-team@company.com',
    incidentGroup: '#auth-incidents'
  })
  .withContext({
    userId: user.id,
    operation: 'tokenRefresh',
    requestId: req.id
  })
  .send();
